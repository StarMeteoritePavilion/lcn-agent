## 教学方式

学习者熟悉 Java 后端，正在学习 TypeScript。每次推进一个完整、可验证的节点：

1. 解释必要概念、源码背景及与 Java 的差别。
2. 给出目标文件的完整参考源码，由学习者手敲；解释关键语法、调用顺序和运行结果。
3. 给出准确命令、预期结果、一个小实验和通过条件。
4. 根据实际输出确认结果，再更新进度；只说明紧邻的下一节点。

用户要求验证时，优先自行自动验证，明确覆盖范围和缺少的证据。
“继续”不自动授权代写后续实现；用户明确授权的修改无需重复询问。
可以更新教学文档和进度，修改实现须有明确授权。已完成手敲并验收的参考副本可删除，
后续阅读直接指向主源码，避免维护两套实现。

## 事实与验收

事实优先级：用户最新指令和实际输出 → 当前源码、配置、测试 → 当前步骤目标 → 学习计划勾选 → Pi 参考行为。
发生冲突时读取证据并说明差异，不自行推断接口、字段、路径或标识符的大小写和结构。

- `[ ]` 表示未实现或未验收；`[x]` 必须有实际命令、结果和覆盖范围。
- 只有代码、类型检查或旧 dist 产物不能证明整个节点完成。运行前重新编译当前源码。
- 实验后确认实验改动已恢复，并核对恢复后的结果。
- 阶段全部交付物和验收项通过后才勾选整个阶段；模拟验证与真实模型验证分别报告。
- 仅维护当前学习节点的验收脚本，通过 `npm test` 执行；阶段结束后记录结论，旧测试可以移除。
  不要求旧测试持续适配新入口，临时脚本不能被描述为仓库内可复跑测试。
- 对未知或中断操作如实记录，不把模型自然语言当作工具成功证据。

## 工作区与协作

主入口为 `src/index.ts`，配置为 `src/core/config.ts`，会话为 `src/core/session.ts`，运行诊断为 `src/core/diagnostics.ts`。
`src/index.ts` 用于当前阶段学习；`src/stage-xx.ts` 保存已完成阶段，不再修改。
阶段涉及独立模块时，用 Git 提交标记完整状态；仅复制入口不能冻结模块版本。
代码单行最多 120 字符，方法职责与关键步骤使用准确中文注释。
保留学习者未提交的修改，不使用破坏性 Git 命令清理工作区。

默认一个 Agent 负责当前节点。需要并行审查时，可委派只读核对文档、源码、测试或 Pi 行为，
明确禁止修改文件、提交和外部副作用。并行写入须划清文件边界，合并前重新读取工作区差异。

## 交接

记录本次节点、完成或待验收状态、修改文件、实际命令和退出结果、覆盖限制、计划更新及下一步。
“阻塞”仅用于无法继续且需要用户提供具体信息或授权的情况。
交付前核对：无无据勾选、无覆盖用户修改、无将参考能力当作已实现能力，文档与代码无未说明的冲突。
