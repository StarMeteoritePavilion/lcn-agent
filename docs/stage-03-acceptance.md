## 修复前的两项失败与复现步骤

1. 提交 `生成期间编辑`，模拟服务暂停返回。
2. 输入 `下一条错`，不按回车。
3. 放行服务端，输出 `模型输出第一行`、`模型输出第二行` 并结束响应。
4. 在恢复的输入提示处按一次退格，输入 `对`，再按回车。

| 检查 | 预期 | 实际 |
| --- | --- | --- |
| 生成输出与编辑行分离 | 模型第一行独立显示 | 屏幕出现 `下一条错模型输出第一行` |
| 继续编辑后提交 | 服务端收到 `下一条对` | 服务端收到 `对下一条错` |

根因：渲染函数直接写 stdout，未协调 readline 正在编辑的行；
`showPrompt()` 调用无参数的 `input.prompt()`，会把编辑光标重置到开头。

修复：展示层合并同一运行事件的输出，通过统一回调写入；交互入口利用 Node 原生
`getCursorPos()`、`moveCursor()`、`cursorTo()`、`clearScreenDown()` 在编辑行上方输出，
再用 `prompt(true)` 保留原光标并重绘。模型、工具、用量、错误和用户消息共用此路径；
非交互错误仍写 stderr。未引入应用依赖。

取消测试原先用提示符判断请求结束；现在生成中也会重绘提示符，因此改为等待实际取消或完成文本，
保留半行冲刷、继续请求及退出断言。
